### 작업 중 특이사항 (참고용)
**M2**: 서브에이전트를 여러 차례 재위임하는 과정에서 이전 시도가 백그라운드에서 계속 실행되며 겹쳐, 한때 3~4개의 에이전트가 같은 파일과 같은 dev 서버/브라우저를 동시에 건드리는 상황이 발생했다. 최종적으로는 파일 내용이 수렴해 정상 동작하는 코드로 귀결되었고, 오케스트레이터(메인 세션)가 정적 코드 검토·독립 테스트 실행·실제 브라우저 조작으로 전부 재검증했다.
**M3**: 위임 도중 세션(Claude Code 프로세스)이 중단되어 에이전트 완료 알림을 못 받았지만, 에이전트 자체는 백그라운드에서 계속 실행되어 작업을 끝마친 상태였다. 다음 세션 시작 시 파일 시스템을 직접 확인해 진행 상황을 파악한 뒤 이어서 독립 검증했다. 브라우저 검증 시 `location.reload()`를 별도 tool 호출로 분리하면 상태가 유실되는 경우가 있었다 — localStorage 시드 → `window.location.reload()`를 **하나의 스크립트 안에서** 실행하는 방식이 안정적이었다.
**M4**: 정적 코드 검토 중 실제 버그를 발견했다 — `stampToday()`가 자유 관문의 사용자 설정(freeGateDefs)을 무시하고 courses.ts 기본 규칙으로 판정하고 있었다(화면 표시와 실제 클리어 판정 불일치). 오케스트레이터가 `src/store/useGameStore.ts`에 `effectiveRule()` 헬퍼를 추가해 직접 수정. 서브에이전트에게 재위임하지 않고 작고 명확한 수정은 오케스트레이터가 바로 처리하는 편이 빠르다.
**M5**: 서브에이전트가 `vite-plugin-pwa`를 설치만 하고 `vite.config.ts`에 연결하지 않아 manifest/서비스워커가 빌드에서 빠져 있었다 — 오케스트레이터가 아이콘(`public/icon.svg`)과 플러그인 설정을 직접 추가해 완성. 코드 리뷰 중 승급 오버레이가 시스템 다크모드의 잉크색을 그대로 써서 노란/초록 띠 배경에 밝은 글자가 겹쳐 대비가 나빠지는 문제도 발견·수정(배경으로 쓰이는 띠 색의 밝기에 따라 고정 잉크색을 쓰도록 변경). 이 세션엔 샌드박스 브라우저 미리보기 도구가 없어 다크모드/설정 화면은 코드 레벨로만 검증했다 — 다음 세션에서 실제 브라우저로 한 번 더 훑어보는 게 좋다.

## 확정된 핵심 결정

1. **사용 대상**: 나 혼자용 (계정 없음, 로컬 저장)
2. **세계관**: 미니멀 UI + 텍스트 조각으로만 존재하는 스토리 (수련 일지)
3. **관문 설계**: 흰띠는 기본 코스 → 노란띠부터 자유 관문 슬롯 해금 → 검은띠 이후 무한 수련 모드 (전부 커스텀)
4. **실패 처리**: 누적 방식 (예: 7일 안에 5번). 승급 보스전만 3일 연속 요구.

### 배포 중 겪은 문제 (참고용)

- 저장소 생성 직후 워크플로우가 `startup_failure`로 실패 반복. 원인은 저장소의 기본 Actions 토큰
  권한이 "읽기 전용"으로 되어 있어 워크플로우가 요청하는 `pages: write` 권한과 충돌한 것 —
  `gh api -X PUT repos/.../actions/permissions/workflow -f default_workflow_permissions=write`로 해결.
- 그 다음엔 GitHub 자체의 Actions/Pages 글로벌 장애(status.github.com에서 확인)와 겹쳐 계속 실패 —
  상태 페이지가 "operational"로 돌아온 뒤 재시도해서 성공.
- `gh` CLI는 winget으로 이미 설치·로그인까지 되어 있었지만 PATH에 없어 `which gh`로는 안 잡혔다.
  `C:\Program Files\GitHub CLI\gh.exe` 전체 경로로 직접 호출해서 우회.
