# 08. 보상 설계 개선 메모 (조사 완료 · 미구현)

> 2026-08-08 조사. **결정만 기록, 코드 변경 없음.** 나중에 착수할 때 이 문서부터 읽을 것.

## 왜 이 조사를 했나

"아주 작은 성취를 반복하는 구조가 ADHD에 도움이 되지 않을까"라는 가설에서 출발.
결론적으로 **가설은 연구로 뒷받침되고, 하루도장은 이미 그 원리에 상당 부분 부합**한다.

주의: 아래는 일반 연구 정리이며 특정 개인에 대한 진단·처방이 아니다.

## 조사 결과 요약

### 1. 지연 할인 (delay discounting)
ADHD는 미래 보상의 주관적 가치가 훨씬 가파르게 감소한다. "나중의 큰 보상"보다
"지금의 작은 보상"을 선호하는 것이 의지가 아니라 보상 처리 회로의 특성.
→ 큰 목표보다 **오늘 하나**가 구조적으로 맞다. (하루도장의 기본 전제와 일치)

- [Scheres et al., Neuropsychologia](https://www.sciencedirect.com/science/article/abs/pii/S0028393205003374)
- [어린 아동 적용 연구](https://pubmed.ncbi.nlm.nih.gov/21083561/)
- [Cortex — 편도체 활성 연관](https://www.sciencedirect.com/science/article/abs/pii/S0010945218301746)

### 2. 토큰 경제 (token economy)
도장·포인트 수집 방식은 ADHD 행동 개입의 검증된 기법. CBT 병행 시 충동성·과잉행동 등
7개 문제행동 범주에서 유의미한 감소. 디지털 버전도 RCT로 효과 확인.

- [CBT + 토큰 경제](https://www.ncbi.nlm.nih.gov/pmc/articles/PMC4659172/)
- [디지털 토큰 경제 RCT](https://www.ncbi.nlm.nih.gov/pmc/articles/PMC12561863/)
- [학교 기반 개입 메타분석](https://www.frontiersin.org/journals/psychology/articles/10.3389/fpsyg.2025.1611145/full)

### 3. 강화 스케줄 설계 원칙 ★ 실무적으로 가장 중요
[PMC7585566](https://pmc.ncbi.nlm.nih.gov/articles/PMC7585566/)의 지침:

| 원칙 | 내용 |
|---|---|
| 즉시성 | 가능한 한 즉시 보상, 지연 경험 자체를 줄일 것 |
| 초기 밀도 | 새 행동 학습 중에는 **매번** 보상(연속 강화) |
| 점진적 축소 | 익숙해지면 서서히 낮추기(100% → 약 20%). 지속성을 만드는 핵심 |
| 급중단 금지 | 갑자기 끊으면 좌절 반응이 큼. 끊을 땐 예고·설명 |
| 보상 다양화 | 행동마다 다른 보상(differential outcomes)이 연합을 강화 |
| 벌은 신중히 | 차감·벌 위주는 오류와 정서 반응을 오히려 증가 |

### 4. 한계 (과장 금지)
- 행동 개입 효과크기는 **중간 정도(moderate at best)**
- 보상 민감도 개인차가 커서 아이마다 반응이 다름 ([PMC8404726](https://www.ncbi.nlm.nih.gov/pmc/articles/PMC8404726/))
- 앱·게임 연구는 초기 단계 — 표본 작고 장기 추적 부족
  ([BrainFit RCT](https://www.jmir.org/2024/1/e55569), [serious games 고찰](https://www.mdpi.com/2414-4088/9/1/8))
- task initiation(작게 쪼개기)은 원리는 타당하나 근거 등급이 위 항목들보다 낮음

## 버전 분기 결정: **나누지 않는다** (별도 앱/주소 만들지 말 것)

"하루도장 2"로 따로 만드는 안을 검토했으나 **기각**. 이유:

- localStorage는 **경로가 아니라 도메인 단위**로 공유된다. `/haru-dojang/`과 가상의
  `/haru-dojang/v2/`는 같은 저장소를 본다. 따라서 새 주소를 파도
  – 새 키를 쓰면 → 기존 진행이 안 넘어감 (사용자 최우선 요구사항 위반)
  – 같은 키를 쓰면 → v1·v2가 같은 데이터를 두고 충돌, 형식이 갈리면 깨짐
  제대로 하려면 마이그레이션 설계가 필요한데 **변경 규모 대비 과하다**.
- 변경 체감이 "반응 문구가 다양해졌다" 수준이라 애초에 메이저 버전 급이 아니다.

**판단 규칙 (앞으로도 적용):**

| 상황 | 판단 |
|---|---|
| 콘텐츠가 다름 (관문 목록·일지 내용) | 버전 분기 **필요** — 한/영이 이 경우 |
| 동작이 상충 (한쪽만 실패 시 초기화 등) | 버전 분기 **필요** |
| 숫자만 다름 (밀도 5 vs 3) | 분기 **불필요** — 상수 하나로 충분 |

이번 건은 전부 세 번째.

## 사용자 요구사항: 한국어판(본인 사용 중)의 체감은 유지 ★

> "지금 쓰는 건 그대로 두고 싶어" (2026-08-08)

사용자는 한국어판을 실사용 중이며 진행이 상당히 쌓여 있다. 두 변경의 성격이 다르다:

| 변경 | 리듬 변화 | 한국어판 기본값 |
|---|---|---|
| 보상 다양화 | 없음 (매번 반응은 그대로, 문구만 다양) | **끔** (사용자 발언을 보수적으로 해석) |
| 점진적 축소 | **있음** (매번 → 가끔) | **끔** |

즉 두 기능 모두 **상수로 켜고 끌 수 있게** 만들고, 한국어판은 기본 꺼짐 = 현재 동작
그대로. 영어판에서 먼저 적용해 관찰한다.

주의: 이 분기는 "영어 = 강화 스케줄"이라는 뜻이 **아니다.** 단지 사용자가 직접 쓰지 않는
빌드가 영어판이라 안전한 시험대일 뿐이다. 나중에 조합이 필요해지면 `VITE_LANG`과
독립된 플래그로 승격할 것(그 경우 `언어 2 × 튜닝 2 = 빌드 4개` 비용 발생).

또한 연구의 "급중단 금지" 원칙은 **사용자 본인에게도 적용된다** — 이미 진행 중인 관문의
보상 리듬을 도중에 바꾸지 말 것. 켜더라도 다음 관문부터 적용되게 설계한다.
