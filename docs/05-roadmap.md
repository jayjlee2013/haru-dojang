# 05. 구현 로드맵

> 원칙: 각 마일스톤은 "실제로 돌아가는 것"으로 끝난다. 완료 선언에는 실행 증거(테스트 결과, 빌드 성공)가 필수. M2가 끝나면 이미 매일 쓸 수 있는 앱이다 — 그 시점부터 사용자가 직접 쓰면서(도그푸딩) 나머지를 만든다.

## M1 — 프로젝트 셋업 + 판정 엔진 (TDD)

**목표**: UI 없이 도메인 로직 완성.

- [ ] Vite + React + TS + Vitest 셋업, git init + GitHub 리포 생성
- [ ] `domain/types.ts`, `content/courses.ts` (흰띠만), `content/journal.ts` (프롤로그 + 흰띠 6편)
- [ ] `domain/day.ts` — dayKey, 하루 경계 (테스트 먼저)
- [ ] `domain/judge.ts` — 누적/연속 판정 (04문서 엣지 케이스 1~7 테스트 먼저)
- [ ] `domain/progression.ts` — 상태 전이 (테스트 먼저)

**완료 기준**: `npm test` 전체 통과 + domain/ 커버리지 90%+ 출력 첨부.

## M2 — 도장(홈) 화면 + 흰띠 플레이 가능 ← 최소 사용 가능 시점

**목표**: 매일 열어서 도장 찍고 관문 깨는 핵심 루프.

- [ ] Zustand store + localStorage persist + schemaVersion
- [ ] 도장(홈) 화면: 현재 관문 카드, 도장 찍기 버튼 + 스탬프 애니메이션, 수련 경로
- [ ] 관문 클리어 연출 → 일지 조각 카드 → 다음 관문 전환
- [ ] 재수련 플로우 (기한 초과 시)
- [ ] 온보딩 (프롤로그 3단계)

**완료 기준**: 브라우저에서 흰띠 1관문 시작 → (dev용 시간 조작 유틸로) 3일치 도장 → 클리어 → 일지 열림 → 2관문 활성까지 화면 녹화 또는 스크린샷. 빌드 exit 0.

**M2 완료 시점에 도그푸딩 시작** — 이후 마일스톤은 실사용 피드백 반영하며 진행.

## M3 — 일지 화면 + 보스전 + 승급

- [ ] 일지 화면 (열림/잠김, 수집 카운터, 세리프 본문)
- [ ] 보스전 모드 (연속 판정 UI, 원 3개, 끊김 처리)
- [ ] 승급 오버레이 (띠 색 전환)
- [ ] 노란띠 콘텐츠 투입 (`courses.ts`, `journal.ts` 확장)

**완료 기준**: 흰띠 보스 → 노란띠 승급 전체 플로우 테스트 통과 + 수동 확인.

## M4 — 자유 관문 + 전체 콘텐츠 + 무한 수련 모드

- [ ] 관문 만들기 화면 (zod 검증)
- [ ] 자유 슬롯 해금 플로우 (노란띠 4번 관문)
- [ ] 초록띠·검은띠 콘텐츠 전체 투입 (일지 25편 완성)
- [ ] 최종 보스전 (10일 안에 7번 — 원래 5일 연속이었으나 변경, 02문서 참고) + 관장 취임 연출
- [ ] 무한 수련 모드: 커스텀 관문 + 일지 2권 (내 기록 쓰기)

**완료 기준**: 전체 진행 시뮬레이션 테스트 (흰띠 시작 → 관장 취임까지 상태 전이 무결성) 통과.

## M5 — 마감 폴리시

- [ ] 설정 화면 (하루 경계 변경, JSON 내보내기/가져오기, 초기화)
- [ ] 다크 모드
- [ ] PWA (설치 가능, 오프라인) — vite-plugin-pwa
- [ ] 접근성 점검 (버튼 라벨, 대비, 폰트 크기)
- [ ] 정적 호스팅 배포 (Vercel 또는 GitHub Pages)

**완료 기준**: Lighthouse PWA 통과 + 휴대폰 홈 화면 설치 후 오프라인 도장 찍기 확인.
